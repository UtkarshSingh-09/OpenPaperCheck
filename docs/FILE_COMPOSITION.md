## 2. The md files you must create (and who reads them)

| File | Location | Purpose | Written when | Updated | Primary readers |
|---|---|---|---|---|---|
| `brain.md` | root | Living memory. First file any human or AI reads. Contains non-negotiables, current state, decision log, glossary, open questions | Week 0 Day 1 | Every week (Sunday) and at each decision | Maintainer, contributors, AI agents |
| `problem.md` | root | Why the project exists; users; gap analysis; hypotheses to test | Week 0 | When evidence changes | Everyone; grant reviewers; mentors |
| `MASTER_PLAN.md` | root | Plan of record; index to all other docs | Week 0 | Monthly | Everyone |
| `AGENTS.md` | root | 40-line rules file for coding agents and new contributors | Week 0 | When commands/rules change | AI agents, developers |
| `ETHICS.md` | root | Policy; wording rules; appeals; privacy | Draft Week 0, final Week 10 | Quarterly | Everyone; legal advisor |

| `docs/research/*.md` | docs/research | Experiments, prototype tests, interviews | As needed | Never (dated notes) | Everyone |
| `docs/incidents/*.md` | docs/incidents | Post-mortems | After incidents | Never | Everyone |
| `docs/community/*.md` | docs/community | Call notes, contributor guides | Monthly | Never | Community |

### 2.1 Rules for these docs
1. **One source of truth per fact.** If a fact lives in `DATABASE.md`, other docs link to it instead of copying it.
2. **Each doc starts with:** Status, Last updated, purpose sentence, table of contents if > 150 lines.
3. **Dates are absolute** (2026-09-28), never "next week".
4. **Mark uncertainty:** write `VERIFY` for anything not checked against the real source.
5. **Docs are code.** They go through PRs; CI runs a markdown link checker and `markdownlint` (relaxed).
6. **Do not put secrets, personal data, or reviewer identities in any md file.**

## 7. Templates

### 7.1 `brain.md` skeleton
```
# brain.md
Last updated: YYYY-MM-DD by <name>
## 1. Mission (2 sentences)
## 2. Non-negotiables (numbered; short)
## 3. Current state (phase, week, what works, what is broken, next 3 tasks)
## 4. Architecture snapshot (5 lines + link to MASTER_PLAN)
## 5. Decision log (D-001 ... newest first: date, decision, why, alternatives, link to ADR)
## 6. Open questions (owner, due date)
## 7. Glossary
## 8. People and roles
## 9. Links
## 10. How to update this file
```

### 7.2 ADR template (`docs/adr/0000-template.md`)
```
# ADR NNNN: Title
Status: proposed | accepted | superseded by NNNN
Date: YYYY-MM-DD
## Context
## Decision
## Alternatives considered
## Consequences (good, bad, follow-ups)
```

### 7.3 Issue template (good first issue)
```
## Goal (one sentence)
## Why it matters
## What to do (steps)
## Files to look at
## How to test
## Acceptance criteria (checkboxes)
## Estimated time
## Need help? Ask in this issue
```

### 7.4 `AGENTS.md` skeleton (keep under 60 lines)
```
# AGENTS.md
Read first: brain.md (Non-negotiables), then the doc for your area.
Commands: make up | make check | make migrate | make e2e
Rules: (fairness) (banned words) (no invented facts) (tests required) (ask before: ETHICS, public signals, auth, new deps)
Where things live: see docs/FILE_COMPOSITION.md
Definition of done: see docs/WORKFLOW.md section 11
```

### 7.5 Research note template (`docs/research/YYYY-MM-title.md`)
```
# Title
Date · Question · Method · Sample · Findings · What we will change · Raw data link
```

## 8. Naming conventions
- Python: modules `snake_case.py`, classes `PascalCase`, functions `snake_case`.
- TypeScript: components `PascalCase.tsx`, hooks `useThing.ts`, files `kebab-case` for non-components.
- SQL: `snake_case`; migrations named `NNNN_description.py` (Alembic revision + slug).
- Docs: UPPER_SNAKE for root policy/plan files, `kebab-case` inside `docs/adr` and `docs/research`.
- Branches: `feat/short-topic`. Tags: `vX.Y.Z` (software), `data-vX.Y.Z` (dataset).
- Signals: `S-###-short-name`. Tasks: `T#` in docs and snake_case in code.
