# API_SPEC.md — REST API (v1)

Status: draft v1 · Base path `/v1` · Format JSON · OpenAPI generated by FastAPI at `/openapi.json`
Frontend types are generated from that file; **the spec here explains intent, the generated file is the truth.**

---

## 1. Conventions

- Errors use **RFC 9457 problem+json**: `{ "type": "...", "title": "...", "status": 422, "detail": "...", "instance": "/v1/check/..." }`.
- Timestamps ISO 8601 UTC. DOIs are always returned normalised (lowercase, no URL prefix).
- Every check response contains `data_as_of` per source and a `disclaimer` string from `ETHICS.md` wording.
- Pagination: cursor-based (`?cursor=...&limit=50`).
- Rate limits (initial; tune from logs): anonymous 60 checks / hour / IP; batch 10 DOIs per call; logged-in reviewers 600 requests / hour. Headers: `RateLimit-Limit`, `RateLimit-Remaining`, `Retry-After`.
- Caching: paper pages send `Cache-Control: public, max-age=300, stale-while-revalidate=3600`.
- CORS: only the web origin.

## 2. Public endpoints (no login)

### 2.1 `GET /v1/check/{doi}`
DOI may be URL-encoded or a full `https://doi.org/...` URL.

Response `200`:
```json
{
  "doi": "10.xxxx/example",
  "state": "retracted_external | needs_review | no_flags_found | insufficient_data",
  "headline": "Retracted according to Retraction Watch and Crossref",
  "paper": { "title": "...", "journal": "...", "publisher": "...", "publication_date": "2021-05-03" },
  "facts": [
    {
      "signal": "S-001-retracted",
      "text": "Retraction recorded on 2023-02-10.",
      "evidence": [
        { "evidence_id": "e1", "source": "retraction_watch", "url": "https://...", "record_id": 12345, "fetched_at": "2026-09-28T02:41:00Z" }
      ],
      "reasons_verbatim": ["<as listed by Retraction Watch>"]
    }
  ],
  "references": {
    "available": true,
    "deposit_status": "deposited",
    "source": "crossref",
    "total": 62,
    "with_doi": 55,
    "without_doi": 7,
    "retracted": [
      { "position": 14, "doi": "10.yyyy/abc", "retraction_date": "2019-04-01", "cited_after_retraction": false }
    ]
  },
  "coverage": { "sources_answered": ["retraction_watch","crossref"], "sources_failed": [] },
  "data_as_of": { "retraction_watch": "2026-09-28", "crossref": "2026-09-28T09:10:00Z" },
  "external_links": { "pubpeer_search": "https://pubpeer.com/search?q=10.xxxx%2Fexample" },
  "disclaimer": "This tool reports sourced facts. It is not a judgement of quality or of any person."
}
```
Errors: `400` invalid DOI (`type: /problems/invalid-doi`), `404` DOI unknown to all sources (returns state `insufficient_data` with `200` **only** if metadata partially exists; otherwise `404` with the same problem body and a helpful message), `429` rate limit, `503` all sources down and no cache.

Behaviour:
1. Normalise DOI → 400 if invalid.
2. Look in `papers`; if fresh, use; else fetch Crossref (and OpenAlex fallback), upsert.
3. Compute state from local retraction data (no per-reference calls).
4. Enqueue background refresh if data is stale (never block the response for it).
Target p95 latency: cached < 300 ms, uncached < 2.5 s.

### 2.2 `POST /v1/check/batch`
Body: `{ "dois": ["...", "..."] }` (max 10 for anonymous). Returns list of compact results (`doi`, `state`, `retracted_reference_count`). Used by browser extensions and Zotero-style integrations later.

### 2.3 `GET /v1/sources`
Lists sources, license, last successful ingest (`ingest_runs`), and record counts. Powers the transparency footer.

### 2.4 `GET /v1/datasets`
Lists dataset releases: version, date, sha256, links, changelog.

### 2.5 `POST /v1/appeals`
Body: `{ "doi": "...", "email": "...", "role": "author|publisher|reader|other", "message": "..." }`. Turnstile token required. Returns `202` with a reference id. Sends acknowledgement email.

### 2.6 `GET /v1/health`
`{ "status": "ok", "db": "ok", "rw_last_ingest": "...", "rw_age_hours": 11 }` (used by uptime checks; no secrets).

## 3. Auth endpoints

| Method + path | Purpose |
|---|---|
| `GET /v1/auth/google/start` | Redirect to Google |
| `GET /v1/auth/google/callback` | Exchange code, create/find user, set session cookie |
| `POST /v1/auth/email/start` | Body `{ "email": "..." }`; sends a single-use link; always returns 202 (no account enumeration) |
| `GET /v1/auth/email/verify?token=...` | Verify link, set session |
| `POST /v1/auth/logout` | Delete session |
| `GET /v1/me` | Profile (display name, level, stats) — never returns email |
| `PATCH /v1/me` | Update display name, languages, fields, leaderboard opt-in |
| `DELETE /v1/me` | Delete account (pseudonymise reviews) |
| `GET /v1/me/export` | Download my data as JSON |

## 4. Reviewer endpoints (login required, role `reviewer` or higher)

### 4.1 `GET /v1/tasks/next`
Returns one leased task or `204` if none. The response contains **only** what the card shows.
```json
{
  "task_id": "uuid",
  "task_type": "ref_match",
  "question": "Is the reference text the same paper as the matched record?",
  "buttons": ["Same paper","Different paper","Not sure"],
  "payload": {
    "reference_text": "…",
    "matched": { "title": "…", "journal": "…", "year": 2018, "url": "https://…" }
  },
  "lease_expires_at": "2026-09-28T10:30:00Z",
  "is_tutorial": false
}
```
Never includes: other reviewers' votes, whether the task is gold, the system's own guess, or the paper's public state.

### 4.2 `POST /v1/tasks/{task_id}/reviews`
Body: `{ "verdict": "yes|no|unsure", "note": "optional ≤ 500 chars", "client_duration_ms": 18400 }`.
Server validates lease, uniqueness, and computes its own timing. Returns `201` and, for gold tasks, `{ "was_gold": true, "correct": true, "explanation": "…" }`. Otherwise `{ "saved": true }`.

### 4.3 `POST /v1/tasks/{task_id}/skip` and `POST /v1/tasks/{task_id}/conflict`
Release lease; log reason.

### 4.4 `POST /v1/reviews/{id}/undo`
Allowed within 10 seconds; deletes the review, reopens the task.

### 4.5 `GET /v1/me/stats`
Weekly count, level, progress to next level, private gold accuracy range, streak.

### 4.6 `GET /v1/leaderboard?period=week`
Opt-in display names only; accuracy-weighted rules from `REVIEW_SYSTEM.md`.

### 4.7 Tutorial
`GET /v1/tutorial/next`, `POST /v1/tutorial/answer` — same shapes as tasks, using gold tasks flagged `tutorial`. Completing sets `tutorial_done_at`.

## 5. Senior / moderator / admin endpoints

| Method + path | Role | Purpose |
|---|---|---|
| `GET /v1/senior/escalations` | senior | List tasks needing a decision, with anonymised vote summary |
| `POST /v1/senior/escalations/{task_id}/decide` | senior | Body `{ "verdict": "yes|no|unsure", "note": "…" }` |
| `POST /v1/gold` | senior | Create gold task with explanation |
| `GET /v1/moderation/appeals` | moderator | Queue |
| `POST /v1/moderation/appeals/{id}/resolve` | moderator | Outcome + note |
| `POST /v1/moderation/pages/{doi}/hide` and `/unhide` | moderator | Emergency hide, logged |
| `POST /v1/moderation/users/{id}/suspend` | moderator | Logged |
| `GET /v1/admin/metrics` | admin | Ingest freshness, queue depth, agreement, source errors |
| `POST /v1/admin/release/build` | admin | Trigger dataset build (dry run by default) |

All write actions on these routes append to `audit_log`.

## 6. Webhooks / integrations (later)
- Optional signed webhook when a paper's public state changes (for library systems). Off by default.
- Browser extension: calls `/v1/check/batch`; shows a small badge; never sends browsing history, only DOIs on the current page, and only on user click.
- Zotero-style plugin: same batch endpoint.

---

## 7. Security requirements for the API
- All state-changing endpoints require CSRF token + session cookie.
- Input models forbid extra fields (`extra="forbid"`).
- DOIs and text fields length-limited (DOI ≤ 300 chars, notes ≤ 500).
- SQL only through SQLAlchemy/parameterised statements.
- Response headers: `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, HSTS at the proxy.
- No stack traces in responses; errors carry a request id.
- Dependency on external sources never blocks the response longer than 2.5 s; use cache and mark stale.
